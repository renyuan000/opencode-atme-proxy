### 2.2 筛选与分诊

- 本地 prefilter + 相关性 LLM。
- 相关/任务/归属/confidence/reason/task hint。
- filter session 一次性创建并在 finally 删除；无状态。
- filter 失败保留消息、游标不前进；失败分类：
  - `model_timeout`
  - `job_timeout`
  - `transport_error`
  - `output_parse`
  - `config_error`
  - `model_error`
- filter 模型曾错误落到 `big-model`，已支持从直接 session 解析 `opencode-go`，并支持 `opencode.filterModel`。
- filter 超时、错误原因、模型、日志路径进入 owner 告警。

### 2.3 任务与审批

- SQLite `state.db`：tasks、task_links、task_events、task_notifications、task_runs、task_tombstones、outbox、task_index。
- 任务状态：candidate / analyzing / needs_info / awaiting_approval / approved / executing / verifying / awaiting_merge / done / rejected / failed / canceled / expired。
- 候选任务（candidate）：不自动分析、不进入 owner 上下文、恢复时不自动续作；默认 14 天归档、90 天 purge。
- 任务分析、开发执行、评审、审批门禁、计划哈希、worktree。
- 任务取消、清理（真删）、归档、恢复、会话查看。
- 任务补充进入 supplements；补充回复使用 Feishu 真 reply（优先原回复目标 → 候选卡/审批卡 → 当前 DM），并带任务标题/taskId/群名。
- 未完成任务恢复提醒；执行中断不自动重放。

### 2.4 上下文、记忆、证据

- 热上下文 `chat-context.json`：50 条 / 7 天。
- 长期证据 `replies/YYYY-MM.jsonl`；`pointer.json` 保持最新月份；`index.jsonl` 可重建索引。
- evidence 记录 `replyToMessageId/threadId`；支持 `findReplyChain` / `findMessageChain`。
- evidence I/O 异步队列；`runtime.stop()` flush；redact/prune 与 append 串行。
- 静态 session context 只 hydrate 一次；`contextKey` 变化/compact 后重新注入。
- 群画像、群摘要、owner direction/keywords、术语、sessionEpoch。
- 记忆分片与 evidence 保留；撤回消息脱敏。
- 图片默认 OCR；原图不进入持久 session；视觉请求走一次性 vision session；图片决策有 current/cluster 区分。

### 2.5 Session 架构

- coordinator：每群/私聊锚点，0 消息是正常设计。
- group summary / dm summary：持久摘要。
- reply/analysis/review：持久 worker。
- execution/review：任务 child。
- filter：一次性 session，正常删除。
- 其他 assistant 任务：`atme:analyze` 等临时 child。

### 2.6 最近新增的清理工具

`scripts/session-cleanup.mjs`

- `plan`：显示 id、title、消息数、字节数、首条 20 字、后续 user 20 字、内容预览。
- 默认只把 0 消息、超过年龄、且不是持久角色的 session 列为 candidate。
- 同标题最新 session、持久角色默认保护。
- `--all` 显示全部 atme session。
- `--include-old-protected` 才允许旧的非当前持久 session 成为候选。
- `apply` 默认模拟；`--yes` 才删除；删除前重新检查。
- `interactive`：↑/↓ 选择、Enter 详情/确认、y/Enter 删候选、Esc/n 返回、q/Ctrl+C 退出；删/取消后回到下一条。
- `--all`：显示全部 atme session，不加年龄条件。
- `audit`：只读列出全部 atme session，不写计划、不删除、不归档；支持 `--json`。
- 列表额外显示“首条 20 字”和“后续 user 20 字”，用于区分系统注入与后到的真实用户补充。
- 默认安全计划候选可能为 0；旧 `atme:chat` 需要 `--include-old-protected` 才可见为候选。

## 4. Session 膨胀结论

实际在 `npb-transform.git` 下观察到约 103 个 session，其中 atme 93 个；空 session 约 17 个，很多是 `atme:chat` coordinator。

原因：

1. `atme:chat` 是 0 消息锚点，本身正常；每个 conversation/epoch/permission 都可能新建。
2. session key 包含 epoch、permission fingerprint、conversation、role、web 模式。
3. `sweepSessions()` 只处理 child；worker/coordinator/group 没有完整 stale sweep。
4. `keepSessions=true` 保留 execution/review child。
5. filter 每批一次性 session；超时/删除失败可能残留。
6. 失败 prompt 可能留下空 worker/child。

当前清理策略：

- 默认保护持久角色；
- 同标题最新 session 永远保护；
- 旧 coordinator 只有在 `--include-old-protected` 下才进入候选；
- 不按 `atme:*` 标题批量删除。

- `07:00`–`09:33`：飞书历史轮询连续失败，`Client network socket disconnected before secure TLS connection was established`；游标未前进，消息保留。期间也有 `read ECONNRESET`。

- `10:49`：流分群新 coordinator；`10:52`：任务 `task_68473f8b6434` 的 analysis-check 超时，保留 deterministic checks。
- `11:48`：私聊请求 `job timed out after 240000ms`。

- `17:37`：资产测绘群摘要超时，300 秒退避。

结论：除模型/筛选问题外，当前还存在**飞书网络/TLS 轮询稳定性、摘要超时、analysis-check 超时、私聊/扫描 job 超时**。这些应纳入 P1 可靠性加固，不应简单归因于过滤条件。

## 8.1 Session probe 加固

`getSession` 现在只把明确的 NotFound（name=NotFoundError 或 status/statusCode=404）视为 missing；网络/5xx/无数据会抛错，SessionManager 捕获后保留现有映射，不新建 session。
